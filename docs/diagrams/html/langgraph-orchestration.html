模式 ① Supervisor 快速路由

direct / nl_compile

简单直接查询：一次路由一次执行，不进任何循环
用最低延迟解决最高频问题（"经济舱通道"）

模式 ② ReAct 事件驱动循环

react_loop

复合查询（一句话多个诉求）：思考→调工具→观察→再思考
保护：签名去重防重复烧钱 + 迭代上限 5 轮防死循环

模式 ③ Coordinator 并行拆解

coordinate → workers

跨模块任务拆成 2-4 个独立子任务，asyncio.gather 并行
拆解用强模型、执行用专职 Worker；非法 Worker 白名单过滤

模式 ④ Plan with SOTA

plan

复杂任务先由 SOTA 模型出计划（步骤/能力/依赖/风险点）
再派发 flash 模型执行——事前规划，成本只加一次 Plan

→
汇总

synthesize

各模式产物统一汇总为最终回答

质量闸口 · Reflection + Advisor

审查不通过 → 先请 SOTA Advisor 三段式诊断（问题/方向/注意事项）→ 有指导地定向重试；Advisor 挂了降级普通重试

一句话总结：不是所有问题都值得让 Agent 思考五轮——按复杂度分流，每一层的职责和成本都可控；每个增强组件（Advisor / 外部 MCP / Rerank）都假设自己会挂，底线能力不依赖任何一个。
