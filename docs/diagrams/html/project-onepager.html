项目简介
一句话讲清楚在做什么
面向结构化业务数据，用 LangGraph 多智能体底座承载自然语言意图，已治理指标走 NL → IR → SQL 两阶段确定性编译，未治理指标走多智能体协作；SQL 经 AST 静态校验 → 执行自修复 → 结果合理性 三层 Guard 兜底，并辅以根因分析与字段级评测，做到口径零幻觉、链路可审计。
2
Agent 底座 · 四大能力
规划 / 记忆 / 检索 / 上下文，Agent 四角全齐
🧭规划与编排
LangGraph StateGraph 14 节点拓扑，Supervisor 路由 + ReAct 执行 + Coordinator 动态组队 + Reflection 自省四模式；Span 追踪定位冗余 LLM 调用，编排延迟 29s → 10s。
🧠三级分层记忆
语义 / 情节 / 程序三层，Milvus 双索引（稠密 HNSW + 稀疏 BM25）双路召回；融合语义 × 时近性 × 重要性三因子排序，写入做冲突检测，长对话不失忆也不串口径。
🗂️上下文管理三件套
Token 触发压缩滑窗 + ContextStore 懒加载按引用召回 + QueryRewriter 指代消解；多轮上下文稳定压在 4K token 内，专治长对话 Lost-in-the-Middle。
📚检索增强 RAG
父子块切片 + 稠密 / BM25 双路召回 + RRF 融合 + Cross-Encoder Rerank；高并发降级，Schema / 文档 / 记忆三库隔离，召回即最小充分上下文。
3
Schema 三层索引收敛
域 → 表 → 字段逐级收敛，只给模型看最小充分 Schema
L1 · 数据域过滤
先按业务语义定位数据域（订单 / 评价 / 支付…），无关域整域排除，候选空间直接缩小一个量级。
L2 · 表级混合召回
域内稠密 + BM25 双路召回 + RRF 融合取候选表，避免全库 Schema 暴力堆进 Prompt，召回即控长。
L3 · 字段级精排
字段级 Cross-Encoder Rerank，抽出最小充分字段 + 样例值 / 枚举值，交给 NL→IR 结构化抽取。
逐级过滤而非全量投喂：表命中率 97.0%，上下文里只有该看的字段
