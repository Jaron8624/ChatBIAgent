混合检索失败

回退为只用稠密向量检索（单路仍可用）

Rerank 失败

直接用 RRF 融合结果输出（不精排仍可用）

Embedding 服务故障

回退纯 BM25 关键词检索（无向量仍可用）

工程原则：每个"增强组件"的异常都必须被捕获并回退——Rerank 调用包在 try/except 里，超时或返回格式异常时记日志、用 RRF 结果继续。用户感知到的只是"这次结果排序略糙"，而不是报错。
一句话总结：召回阶段放大 K 保覆盖（宁多勿漏），精排阶段收敛保精确——先捞全，再选准；任何一层增强挂了，都有更朴素但可靠的上一层兜底。
