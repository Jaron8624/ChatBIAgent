父子块切分（Parent-Child Chunking）

核心思想：用小（子）块保证检索精度，用大（父）块保证回答时的上下文完整
① 入库阶段
输入

退款政策.pdf

PyMuPDFLoader 加载全文

→
两级切分

DocumentProcessor

parent_splitter：先切大父块（保留完整段落语义）

child_splitter：对每个父块单独再切细粒度子块

→
去重关卡

sha256 内容哈希查重

每个子块算哈希，批量比对已入库哈希——重复块直接跳过，知识库可反复增量入库不膨胀

子块 → Milvus

子块生成 Embedding 写入向量库，metadata 携带 parent_id + child_chunk_hash
检索只面向子块

父块 → PostgreSQL

父块原文按 parent_id 存储
不负责检索，只负责取回完整上下文

▼
② 切块实际长什么样
父块 P1（约500字）：退款政策：一、配送超时订单的退款规则。1. 超时15分钟内…… 2. 超时15-30分钟赔付5元…… 3. 超时30分钟以上……
  ├─ 子块 P1-C1：超时 15 分钟内不支持退款
  ├─ 子块 P1-C2：超时 15-30 分钟赔付 5 元红包
  └─ 子块 P1-C3：超时 30 分钟以上支持全额退款并赔付 8 元
▼
③ 查询阶段："超时 20 分钟能退吗"
Step 1 精准命中

向量检索命中子块 P1-C2——细粒度子块精准匹配"15-30 分钟"区间

→
Step 2 取回父块

按 parent_id 到 PostgreSQL 取回父块 P1 完整条文

→
Step 3 完整作答

完整条文注入 Prompt，模型基于完整上下文生成回答

一句话总结：检索的精度由子块保证，回答的上下文完整性由父块保证——解决"切小块召回准但上下文残缺，切大块上下文全但召回糙"的两难。
